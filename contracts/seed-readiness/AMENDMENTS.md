## Requirements replaced after a red-team round

A requirement is replaced, never silently removed, only when a round's answer names it as contradictory or impossible; the next round judges the replacement.

- SR-0.03 T2: requirement replaced after red-team round 2 answer 1 (uncommitted changes were BLOCKED while round-1 criteria expect FAIL for them, the vault's own commits carry no trailer, and a rebase, a merge of main or an amend failed every task for good). From: "scope is judged per task on the task's own commits: every non-merge commit in base..HEAD carries a trailer Contract-Task: <contract id> <task id> naming exactly one task of the contract (the owner rule of one task per commit); a task's scope criterion checks the files of the commits that name it and fails naming any commit that names no task or a task outside the contract; uncommitted changes make every scope criterion BLOCKED with commit the work". To: "scope has one semantics. The range is the commits reachable from HEAD and not from the recorded base nor from the main ref at verify time, so a rebase onto main or a merge of main never brings main's own commits into it. ...".
- SR-0.03 T1: criterion replaced after red-team round 2 answer notes, point 2 (the DSSE payload is the canonical hash string, not the contract (vendor/attest/signature.mjs:29-34), so the round-1 wording could not be met). From: "the decoded DSSE payload has base.sha". To: "the signed contract JSON (whose canonical hash the DSSE payload carries) has base.sha".
- SR-1.05 T1: requirement replaced after red-team round 2 answer 1 (keyed on configuration, every quick-tunnel caller shared the loopback socket, so anyone could lock the owner out, and test/oauth.test.mjs could not pass beside the new test). To: "the remote rate-limit key follows the tunnel that actually carries the request, passed into createServer by the daemon (activeTunnel()); see the requirement in the spec for the full rule".

## Test-name guards added by the build

node's TAP output counts each test file as a passing test, so a name filter that matches nothing exits 0 and prints '# pass 1' (measured on node 23.7, 31 October 2026). Each command below that filters tests by name now requires, for each alternative of its filter, a passing test line whose test name matches it; a skipped or todo test, a file line and a describe() suite line never count, and anchors in the filter apply to the test name. Statements are unchanged.

History of the guard's form, 31 October 2026: (1) a count of matching passing lines against the number of alternatives (grep); (2) the same count, with describe() suite lines dropped (awk); (3) one match required for each alternative, matched against the test name, because a count let two tests matching one alternative stand in for another that never ran; (4) each alternative that is a test name, not a label, anchored at both ends, because a name that was a prefix of another criterion's test name in the same file let that test stand in for one never written.

- QL-1.03: name guard on 25 criterion command(s).
- QL-1.04: name guard on 24 criterion command(s).

## Subtest labels added by the build

When two or more red-green criteria of one task shared one whole-file command, one failing subtest at base and a green file passed them all (reviewer's finding, 31 October 2026). Each such criterion now runs its own subtest, named <task>-cNN: after its position in the task; the task gains a requirement naming the rule and a command criterion that one full run passes every labelled subtest with nothing skipped. Statements are unchanged.

- QL-1.01: 34 criterion command(s) narrowed to labelled subtests.
- QL-1.02: 27 criterion command(s) narrowed to labelled subtests.
- QL-1.03: 25 criterion command(s) narrowed to labelled subtests.
- QL-1.04: 11 criterion command(s) narrowed to labelled subtests.

## Subtest labels renumbered by the build

A criterion that arrives already filtered to a subtest label, as a red-team answer's own criterion does, is renumbered so that NN in <task>-cNN: is its position in the task, and its label joins that task's full-run criterion for the file, so the full run also checks it for skips and todos (reviewer's finding, 31 October 2026). A build lint fails on any label whose number differs from its position or which no full-run list names. Statements are unchanged apart from the full-run criterion's list of labels and a label that starts a statement, which is renumbered to the criterion's position the same way.

- QL-1.04: 13 labelled criterion command(s) renumbered to their position and added to the full-run list, and 11 label(s) that start a statement renumbered with them.

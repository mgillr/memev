### Changed
- `memev_recall` clamps `limit` to 1-10 whatever the caller sends, and `offset` pages through the remaining hits up to offset 1000. The text is still the JSON array of hits; when more hits match than the page shows, one line follows the array in the shape `memev_get` and `memev_list` use, for example `Showing hits 1-10 of 25. Call memev_recall again with offset 10. 15 hits remain.` The structured result carries `total` and `next`. A client that parses the whole text as JSON reads the array up to its closing bracket; the line holds none.
- Recall asks the index for the matches up to the end of the requested page, not for every match, and an offset past 1000 returns an empty page, so one call never asks the index for more than 1,010 hits. `next` is null once the next page would start past 1000; the line then says that recall does not page further and to narrow the query.
- The HTTP recall route takes `offset` and returns `total`, `offset` and `next` beside the hits and the text. `total` counts the matches before the route's score bar and its exclusions, so a page can hold fewer hits than the limit while `next` still points on.

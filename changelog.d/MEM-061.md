### Added

- `memev runner on <seat> --max-runs-per-day N` turns on an opt-in background runner for a seat: while `memev runner watch <seat>` runs, every task the operator posts to the seat starts a headless turn of the seat's app, at most N runs a day. It is off by default and there is no default limit: the runner refuses to start without one. `memev runner status` shows what is on and how many runs each seat has had today; `memev runner off <seat>` stops it.

### Fixed

- The runner's cursor is per computer and it remembers the tasks it has already run, so a task is not run twice when another computer's log syncs in and the messages' numbers move, and a task that syncs in with an earlier stamp still runs.
- A task to a seat by an earlier name (before a rename) starts a run, as a task to its current name does.
- Only a task that really comes from the operator (the terminal on this computer, or the operator seat on its own computer) starts a run; a log line with the operator flag set by another computer no longer does.
- The task body goes to the app on stdin, so a body that starts with a dash is the prompt, not an option.
- One watch per seat: a pid file keeps a second `memev runner watch <seat>` from starting while the first still runs; a stale file is replaced.

### Added

- `memev connect cursor --project <dir>` writes an always-on rule to `<dir>/.cursor/rules/memev.mdc` (`alwaysApply: true`), so the memory rule is in every session of that project, not only at session start. `memev disconnect cursor` removes it. The Cursor stop hook continues the session with a `followup_message` when an operator task is waiting for you, and CLIENTS.md documents Cursor's hook limits.

### Fixed

- The Cursor prompt hook no longer marks waiting bus messages read: it peeks, so a task that is already waiting when the person types still gets the stop hook's follow-up, and the stop hook marks the tasks it followed up on as read.
- The follow-up loop limit now lives where the desktop client reads it: `loop_limit: 3` on the stop entry in `~/.cursor/hooks.json`, instead of a field in the hook output that the client ignores. The hook also stops following up once its `loop_count` reaches 3.

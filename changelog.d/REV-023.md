### Added

- `memev project` shows the project name a folder's memories are filed under and where it came from (a pin, the git top-level folder, or the folder itself), and `memev project set <name>` pins a name for a repository or folder in the vault config, which the hooks use from then on.
- Project slugs keep Unicode letters and digits, so a Japanese or Cyrillic folder name gets a stable project name of its own instead of `untitled`.

### Fixed

- A folder name the old slug rule already gave a name for keeps that exact name, so memories, checkpoints and graph links filed before an upgrade are still found. Names the old rule could not name (Japanese, Cyrillic and other non-Latin) now get their own slug; memories already filed under `untitled` stay there.
- Indic names keep their vowel signs, so two names that differ only in a vowel sign no longer collapse to the same project.
- The project name is resolved through the folder's real path, so a pin set on a folder reached through a symlink still matches.
- `memev project set` refuses a name with no letters or digits, which would pin the shared `untitled` project.
- A long slug is cut by code point, never in the middle of a surrogate pair.

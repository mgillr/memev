### Added

- A person can bind a role to their own SSH key, verifiably and offline: the role's public key is signed with OpenSSH (namespace memev) and stored beside the role, and it verifies against an allowed_signers file.
- The setup step does the checks, the role key pair when absent, the bind and the receiver-side trust line in one rollback-safe step: on failure every file it wrote gets its previous bytes back or is removed and every directory it made is removed; it keeps a matching binding and refuses to replace a binding to a different principal or key.
- Binding degrades cleanly when OpenSSH is missing or older than 8.0, with one clear message and the keys directory left untouched.
- A binding vouches for one role name, one principal and the role's public key: the signed message names all three, so a bound role's files copied under another role name do not verify.
- A role name is one plain file name (letters, digits and . _ -, never a leading dot or dash, no slash); any other name is refused before anything is written.

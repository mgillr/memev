### Added

- The canonical project schema, version 1 (`docs/schemas/project-v1.json`): every entity type of the project store declares its owner (a subject type of the identity model), its scope version field and its merge class (last-writer, set-union, append-only or human-resolution). The owner is a declaration, not an enforcement, not the memory authority of ADR 7 and not the permission matrix of ADR 5. The store holds the same declarations, refuses an entity of a type that declares no merge class, and refuses a type that takes the name of a built-in one. The core records the class and applies none. The lease class and the `service` owners of lease, evidence and event are marked provisional.
- Two incompatible approvals on one task are a semantic conflict, whatever versions they were given on. Each approval write is its own event, so two writes with one id still conflict. The conflict is derived from the log and read through `store.conflicts()` and `store.view('task')`, which shows a live task as `CONFLICTED`. It is never written into a stored task, and a terminal task is not shown as conflicted. An approval whose `resolves` lists events of the same task, naming both an approve and a reject, ends it; the write is refused when it does not, and a converged log that does so is ignored and reported on replay.
- `docs/PROJECTS.md` documents the merge classes, which entries are provisional, and the semantic-conflict rule with the choices made on `task_version` and on who may settle.

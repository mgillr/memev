# Decomposition of the notes (2026-10-31)

Part of the [programme decomposition](README.md). Up: the [documentation index](../../README.md).

Source: the owner's message and attached notes of 31 Oct 2026. IDs: MV-* requirements are in REQUIREMENTS.md; DEC-* decisions, REJ-* rejected or corrected items and OQ-* open questions are below. Nothing here is signed or accepted; it is a proposal for the owner.

## Decisions and convergence points

- DEC-01: Memev is distributed operating infrastructure, not an agent-memory application (stated repeatedly by the owner). (agreed)
- DEC-02: crdt-merge is the convergence substrate; Memev owns what the state means. (recommended, agreed in direction; conflicts with SR-3.01 plan (see OQ-02))
- DEC-03: Federated state engine is a foundational dependency, not a paid utility; paid multi-computer merge is the first demonstration. (recommended)
- DEC-04: Do not build a second CRDT engine; do not merely bolt crdt-merge onto git conflict resolution. (recommended)
- DEC-05: Split architecture: Memev operating layer on top of CRDT state, causal sync, trust and identity, evidence and receipts. (recommended)
- DEC-06: Not every object uses the same merge semantics (nine object classes listed). (recommended)
- DEC-07: Replication is separated from acceptance. (recommended)
- DEC-08: A canonical operation envelope is specified before integrating everything. (recommended (insisted))
- DEC-09: Engineering priority P0 CRDT audit, memory integration, event model; P1 gossip, project state, trust, receipts; P2 federated org model, cross-language, public benchmark. (recommended)
- DEC-10: Three next deliverables: conformance audit, integration design, three-node prototype. (recommended)
- DEC-11: Keep the CRDT engine in its own repo under BSL 1.1; Apache-2.0 core; ACFA-RS own licence; federated services commercial. (agreed (the owner raised the licence constraint))
- DEC-12: Free core gets strong recall (BM25, graph, temporal, optional local semantic, trust-aware); paid gets convergence and federation; free recall is not weakened. (recommended)
- DEC-13: Memev Operating Environment, Federation and Network as three ambitions in that sequence. (recommended)
- DEC-14 (not adopted): Distinct Federated tier (not 'Corporate with more computers'). (recommended; not adopted by the owner decision of 31 Oct 2026 (OQ-01))
- DEC-15: Support MCP and A2A; no replacement protocols; no proprietary agent runtime; integrate rather than migrate. (recommended)
- DEC-16: Entry sequence: interoperable and accountable first, then federation demonstrator, then commercial network; first wedge engineering/industrial. (recommended)
- DEC-17: Roles: CRDT-Merge converges, ACFA-RS admits and reconstructs numeric contributions, E4 governs trust, Proofline verifies acceptance, Memev decides authority. (recommended)
- DEC-18: Reconcile requirements, PRs, contracts and decisions first. (recommended)

## Rejected or corrected

- REJ-01: Claim that Mem0 'gave up'/'admitted defeat' on conflict resolution. Corrected: ADD-only was a deliberate design choice (16 April 2026). Converge README still carries the old wording.
- REJ-02: Treating the free core recall as plain `get`. Corrected: BM25 with graph, review state and feedback already exists.
- REJ-03: Framing Memev as an agent-memory application or comparing it feature by feature with Mem0/Letta/Zep.
- REJ-04: Claiming nobody else is building agent infrastructure or that the market is unoccupied (MCP, A2A, AGNTCY, hyperscalers exist).
- REJ-05: Building a second CRDT engine inside Memev, or only connecting crdt-merge to git conflict resolution.
- REJ-06: One CRDT for every project object.
- REJ-07: Using ACFA to aggregate arbitrary text memories or to average agents' confidence scores.
- REJ-08: Assuming mathematical deltas alone satisfy GDPR or privacy; assuming a redacted receipt equals secure aggregation or DP.
- REJ-09: Competing on memory-extraction benchmarks with Mem0 or on orchestration features with LangGraph; replacing MCP or A2A.
- REJ-10: Deliberately weakening free recall to force upgrades.
- REJ-11: Putting the licensed CRDT implementation into the Apache-2.0 core.
- REJ-12: Equating 'replicated' with 'verified', 'validly signed' with 'true', 'converged' with 'completed correctly'.
- REJ-13: Launching the whole architecture at once; opening dozens of implementation PRs before interfaces are agreed.
- REJ-14: Federated tier as merely 'Corporate with more computers'; machine-count licensing as the eventual enterprise model (caveated, not rejected outright).
- REJ-15: Treating healthcare as automatically the easiest first market (procurement is slow); use it as the sovereignty demonstration.
- REJ-16: Treating the 27-draft-PR inventory line as live truth.
- REJ-17: Scores in the notes (9.5/10 etc.) as measurements; they are judgement, no suites were run.

Whether a distinct federation offer exists above that is still undecided; federated sites (addendum recommendation 13) need explicit acceptance.

Probably both layers (structured replicated state vs Markdown text merge) but no document says so.
- OQ-03: ACFA-RS and ACFA patent position and distribution terms (acfa-rs LICENSE is Apache-2.0; patents not checked).
- OQ-04: Licensing lawyer review of the combined distribution against the BSL use restriction.
- OQ-05: Which envelope fields are normative and how they relate to the existing oplog hash/hlc/dev record (ADR 2 is open).
- OQ-06: Which privacy mechanism (minimisation, secure aggregation, differential privacy) applies to which data class when federating.
- OQ-07: Cross-language: are the TS, Rust and Java editions wire-compatible with the Python reference today? Unknown; no shared vectors.
- OQ-08: First commercial wedge market (notes lean engineering and industrial programmes).
- OQ-09: Task ownership lease semantics (ADR 3 open) and permission matrix (ADR 5 open).
- OQ-10: Where the transport adapter lives so that it stays in the open core without containing a standalone merge service (BSL use restriction).
- OQ-11: Positioning line: 'Federated Agent Infrastructure' versus 'distributed operating infrastructure for human and autonomous work'.
- OQ-12: BSL change date 2028-03-29 converts crdt-merge to Apache-2.0: does the paid-engine strategy still hold after that date?

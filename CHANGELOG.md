# Changelog

## Unreleased

### Added

- A short animated demo video in `Demo Video/` shows how each tier works and how the tiers connect, with a GIF preview linked from the top of the README and the script that draws it.
- docs/roadmap/add-ons.md lists the planned add-ons and services for Business and Enterprise, and docs/custom-modules holds the custom module use cases and walk-throughs, each with acceptance checks.
- `docs/ARCHITECTURE.md` shows what runs today, module by module, and one chart each for Personal, Business and Corporate. Business shows members' computers (Memev and local tools) syncing into one company vault that the admin console can see and search, one AI provider for the organisation (a cloud AI service or an on-premises LLM, over MCP), the paid crdt-merge convergence engine and relay, and a licence server that exchanges licence information only.
- `docs/MODULES.md` is the module interdependency map. `node scripts/docs/module-graph.mjs` writes it from the real imports in `bin/` and `src/` (a layer summary, a graph of every module and a per-module table), and `--check` and `test/docs-module-map.test.mjs` fail when it is out of date.
- `docs/CONVERGENCE.md` and a README section explain the paid core: the Memev core is Apache-2.0 and free, the convergence engine crdt-merge lives in its own repository under its original licence (currently BSL 1.1) and is called as an external dependency, never vendored, and only licence information passes between an install and our side.
- `docs/README.md` indexes every page and links back up; every page under `docs/` now links back to it. `docs/DEVELOPING.md` lists the checks to run, and `test/docs-links.test.mjs` fails on a broken relative link or anchor, a page that cannot be reached from the index, or a README that does not open with the centred video poster.
- `memev ready` waits for each connected app's first session and prints "<app> joined at HH:MM", then "Ready: <app> and <app> share one memory" once one app recalls a memory another one saved. `--timeout` exits non-zero and names the apps that did not join. It only reads the vault.
- `scripts/install.sh` and `scripts/install.ps1` install from a release tarball after checking its SHA-256, then restart from the installed copy. The URL must be https or a file URL. `scripts/release-tarball.mjs` builds that tarball and the checksum file. No download address is built in.
- `memev bus hello <seat>` posts one hello to a seat, says what to do in the app, and waits for the seat to read it on its next turn, or exits 1 at the timeout.
- The installers fetch a pinned Node 22 runtime when no Node 22 is on PATH, check its SHA-256, and run from that copy. The address and checksum for each platform are in `scripts/node-runtime.json`, and the same pins are carried in the installer scripts.
- A later install reuses that copy when its version matches, in a folder named for that version, and leaves a running copy in place.
- Contracts are opt-in: off by default for new installs, on for existing vaults. `memev contracts on|off|status` controls the flag. When off, the Stop hook never blocks on a contract.
- Cloud access for cloud AI apps is off by default on a fresh install. `memev init` offers it once on a terminal, the checklist says `memev cloud on` in one line that names what recall returns and to whom, and the tunnel binary is only downloaded once you switch it on. A vault that already has a setting keeps it.
- `memev init --local-only` and `memev init --org` skip the question and start with remote access off.
- Cloud seats on the bus post only to the operator by default, and a body from a seat that does not speak for you is shown as untrusted data, not instructions, and cut to a shorter cap. A vault setting (bus cloud_tasks) lets a team allow a cloud seat to assign a task to a local seat.
- `memev bus tasks` shows `waiting for next turn` for an unclaimed task to a live seat that has not read it yet.
- The init checklist says plainly that apps answer between turns.
- On Free, enrolling a second computer now says "Free covers this computer. Adding more computers is part of Personal (up to 3 computers). Run memev upgrade to see plans." instead of telling the user to remove a computer that cannot be removed. The count comes from the entitlement table, and the text is shown only at that moment, never in the resume card or the AI context.
- `memev upgrade` prints the checkout URL from this vault's config. Checkout is Stripe in test mode. Product ids, prices, and the computer cap come from config. The licence email From address is `MEMEV_LICENCE_FROM`, and the licence endpoint URL is configuration. No address, host, or IP is built in.
- docs/REFERRAL.md, the referral credit mechanism spec: a Stripe checkout referral code, opt-in only, one free month of Personal for the referrer, with no in-app tracking and no telemetry. docs/PRICING.md now has a Referral credit section that points to it.
- An install page an AI app can follow, a setup page for each supported app, and draft text for an MCP directory entry and a connector directory entry. The drafts are not submitted.
- docs/METRICS.md records where the counts are kept: licence-activation counts beside the licence endpoint, download counts from npm and the release host, and the milestone report URL from configuration. No address, host, or IP is built in.
- On Windows, `memev service install` creates a per-user Task Scheduler entry that starts the daemon at logon (`schtasks /create /sc onlogon`), and `memev service remove` deletes it. The daemon now spawns with `windowsHide`, so no console window appears.
- A Windows job (windows-latest) runs the Windows-specific tests (app registration, settings files, hooks, MCP, the doctor) on every push to main and on release tags, never on pull requests. The quickstart and the Windows 11 lab section now say apps are registered with node.exe and the runtime script, not the .cmd launcher.
- When a network blocks port 22, the GitHub backup fetches and pushes are retried through ssh.github.com on port 443, and `memev doctor` checks that GitHub is reachable and says how to fix it, including pushing over HTTPS with a fine-grained token for the one repository.
- An opt-in, off-by-default "Made with Memev" footer on exported hand-offs (the resume card) and contract summaries (`memev contract status`). I turn it on by setting `footer: true` in the vault config. It appears only on artefacts I export and share, never in private notes.
- A licensing notice (docs/LICENSING-NOTICE.md) that announces the decided direction: the Memev core stays Apache-2.0, and the convergence engine will be released in its own separate repository under the Functional Source License 1.1 with Apache 2.0 as the future licence (FSL-1.1-ALv2), where each version becomes Apache-2.0 two years after it is made available.
- A one-line positioning statement in the README and docs/COMPARISON.md, which compares how Memev works with a typical hosted memory service using public facts and cited sources.
- `memev connect <app>` now exits non-zero when the named app could not be connected, for example when its settings file cannot be parsed. `memev connect all` still exits 0 when an app is left for manual steps and the others connected.
- Seat names now use the short machine name (for example, my-app@my-laptop) instead of the fixed word "host".
- `memev bus rename <old> <new>` renames a seat and keeps its history; the old name still finds it.
- Connecting Cursor now adds a checklist note: check Settings → MCP shows memev connected, and allow its tools.
- In a container the server trusts only the bridge gateway (the host, found from the default route; `MEMEV_GATEWAY` overrides it) as local, instead of every private-range peer. docs/DOCKER.md says to keep the port published on the host's loopback only, and what changes if it is not.
- `memev github setup --host <ghes>` for GitHub Enterprise, and `memev backup set <git-url>` for any private git remote.
- The lab plan has a failure case for each path found in the review: a missing git, a port in use, a second vault, a Node upgrade, a second computer, a proxy and Windows. `test/fail-paths.test.mjs` walks the four a Linux machine can stage on its own: the failure, what Memev says, and the way back.
- I add regression guards for the strengths that already work: uninstall restores every client file byte for byte, the hook output of each app keeps its documented format, the bus writes one message file per device, a licence verifies offline, and the doctor bundle stays secret-free on a local-only vault.

### Changed

- The demo video in `Demo Video/` is re-rendered for the tier model with a personal vault on one or more computers, and work vaults and a company vault for Business and Corporate (both marked coming). It adds the hard boundary, what happens when someone leaves, and a scene on what the paid engine does, and it holds each caption long enough to read. It shows no prices.
- The demo video in `Demo Video/` is re-rendered with a neutral corporate look: an off-white background, charcoal and navy text, one muted steel-blue accent, thin strokes, flat nodes and calm fades. Caption and label contrast is checked against WCAG AA by a built-in audit (`--audit`).
- Each slide now stays on screen for as long as its text needs. One function in `make_memev_tiers.py` works out the hold from every visible word and every diagram element, never changes a slide while it is still animating in, and prints a per-scene timing table during the render. The film is longer as a result.
- New scenes: a Business trial (free for 14 days, extendable once by 14 days, no card needed), how each function (senior leadership, heads of department, PMO, Sales, Engineering, BD and corporate functions) reads and promotes, business reports and business modules, Corporate scopes, a Business deployment-options scene (cloud-hosted and managed by us for teams that use external hosted AI providers, with a free self-serve trial, or on-premises and self-hosted for teams that run an internal model or have strict data residency, set up as a paid service with a one-command Docker package), an optional secure remote setup that the customer starts (outbound only, time-limited, logged and revocable), and a guided Corporate pilot. Business and Corporate stay marked coming, and the reports, modules, trial and pilot are marked planned.
- The Personal more-computers scene no longer says "or a teammate". The Business invite scene says an organisation admin invites members into the company vault, bus only by default, with full access as a role. The leaver scene adds that the work vault is kept for the company for 30 days.
- The video shows no prices and no seat or computer counts.
- The README opens with the centred demo video poster (linked to `media/memev-tiers.mp4`), the title, badges and links. The 4 min 53 s cut with "Coming Soon" labels replaces the earlier 14 min 35 s video and GIF, which moved from `Demo Video/` to `media/`, outside the npm package.
- Pricing is now Personal with more computers at $12/month or $120/year (CHF 10 or CHF 100). Business and Corporate have no public price, and the Team and Enterprise columns are gone from `docs/PRICING.md`. The pricing tests hold the new figures and fail on a price from before 28 October 2026.
- Business and Corporate are described as one model: one company vault (Business) or one main corporate vault (Corporate) that all members' work data syncs into and the company can see and search, and one AI provider per organisation, either a cloud AI service or an on-premises LLM. Members keep private work outside Memev. A licence counts once per organisation, by person and by computer. The Business trial is 5 members and 10 computers, self-serve for one hosted cloud AI provider, with a sales-assisted pilot for on-premises, air-gapped and compliance-led organisations. All of it is marked planned. This replaces the work-vault-per-member wording.
- Personal is described as several cloud AI apps side by side (Claude, ChatGPT; more coming soon) plus local coding tools over MCP.
- `docs/LICENSING-NOTICE.md` names crdt-merge and its licence, and `CHARTER.md`, `SECURITY.md`, `docs/ISOLATION.md` and `docs/CONVERGENCE.md` say plainly what leaves a computer: a licence key on activation, the opt-in milestone report, and nothing from the vault.
- The tier pages, the README and the related docs now describe four tiers: Personal on one computer (free), Personal with more computers (paid), and Business and Corporate (both marked coming). There is no Team tier: teammates join a company vault through an org admin's invite, on the business side only.
- Business and Corporate are described as one model at two scales: a work vault for each member plus a shared company vault, with promote and share up and company knowledge down. A personal or home vault never crosses into either, and anyone who leaves a company loses all vault access.
- The free tier is described as one computer at a time through your own GitHub. Git sync is single-writer backup, and a second computer that pushes gets a warning that concurrent edits can conflict. Editing on two machines at once is the paid tier and relies on a separately licensed merge engine that is not part of this repository.
- The tier pages for Business (`docs/tiers/business.md`) and Corporate (`docs/tiers/corporate.md`) replace the Business and Enterprise pages, and `docs/tiers/team.md` is removed. A Business trial is planned.
- On Windows, the MCP and hook entries I register in your AI apps point at node.exe with the runtime script as its first argument, never the memev.cmd launcher: since Node's CVE-2024-27980 fix, a Node app cannot spawn a .cmd file without a shell.
- The Tailscale provider now uses `tailscale serve` (tailnet only) instead of `tailscale funnel`, so a joined computer reaches the vault over the tailnet and the address is never opened to the public internet. Stopping turns off only the serve listener Memev started.
- Licence activation stores the relay address from the licence service reply when that reply includes one. A Personal licence in its grace period still uses that address.
- Licence activation ignores a relay address in the reply when it is not a relay URL.
- A valid Personal licence uses the relay address already stored in the vault config when `memev cloud relay on` is given no address. No address is built in.
- Settings files with comments or trailing commas (VS Code, Zed, Gemini CLI) are now connected: Memev edits them in place and keeps every comment and the layout, where it used to refuse them and ask for a manual step. Disconnecting gives back the original text. The JSONC editor is jsonc-parser 3.3.1 (MIT), vendored with its checksums.
- When Memev cannot edit an app's config (a file that does not parse, or that is not a JSON object), the checklist names the file and says why, instead of only "memev connect <app>". `memev connect <app> --print` prints exactly what Memev would add to each of that app's files, to paste by hand, and changes nothing. Once it is pasted, `memev connect <app>` finds itself already there.
- The pricing table sells only what is built: member keys get their own row, marked planned for Team, Business and Enterprise, apart from the shared vault and provenance that work today. A new row names one memory for every AI app and the comms bus between them, and the page says Personal is sold for what exists today. A test fails if any planned feature is ticked as included.
- The end of `memev init` leads with "Ready: <app> and <app> share one memory" (or "Not ready" and why), then at most two steps that need you: restart the apps and choose the lead AI. GitHub backup, cloud access, start at login, the PATH and the anonymous report come after, under "Later, optional".
- docs/BUS.md and the bus tool descriptions show seat names in the machine-name form (`claude-code@my-laptop`), say that older vaults keep their `@host` seats, and point to `memev bus rename`.
- `memev_get` returns a long note in pages of at most 8,000 characters, cut at a line, and says the offset to pass for the next page. A heading reads that section the same way. A short note still comes back whole.
- `memev_list` returns at most 50 notes at a time, with the total and the offset for the next page. A shorter folder comes back whole. Session journals are listed newest first.
- After a compaction the session-start hook sends the resume card alone, without the rules or the no-lead notice, and on resume it sends nothing when this session already holds the same card; a changed card is still sent, and a startup or clear still gets the rules and the card. In the benchmark a compaction falls from 1,320 to 1,041 tokens (the card) and a resume with nothing new from 1,290 to none.
- Changes no longer edit CHANGELOG.md: each adds a note in changelog.d/ (see changelog.d/README.md), and `node scripts/changelog-assemble.mjs` folds the notes in at release. The pull request check fails any other edit of CHANGELOG.md.

### Fixed

- The quickstart lists the real vault layout (`memory/<kind>/`, `work/sessions/`, `bus/`), says Memev starts at login on Windows through a Task Scheduler entry, and no longer says a personal install keeps remote access on by default (it is off on every install).
- The lab test plan, the problems page and the custom-module walk-throughs match the one-company-vault model, comment-preserving edits of settings files, and the Windows login entry.
- The leak scan accepts `git@ssh.github.com`, the SSH host of the port 443 fallback, as a remote and not as an e-mail address. Real addresses and look-alike hosts are still flagged, and a test covers both.
- After a Node upgrade that removes the old Node (nvm, fnm, Volta, Homebrew), Memev keeps working in every app. The launcher runs node from PATH when it is Node 22 or newer, and otherwise the Node recorded at install. That Node is recorded by its name on PATH (such as /usr/local/bin/node) when the name points to the same Node, so an upgrade that moves the link keeps it working. When neither is there, the launcher says so, and `memev doctor` fails its launcher check with the install command and `memev doctor --fix`.
- The leak scan allowlists the single line of commit 6f21fc3 that carries GitHub's default merge subject for PR 55, so history scans stay clean without rewriting history (same precedent as the PR 7 merge subject).
- The test that doctor shows no two-vaults warning with a single vault now holds the 99 ports above its vault with listeners of its own while it runs. Before, another test's daemon started in that range by a test running side by side answered doctor's probe and failed the test at random.
- `memev bus hello operator` now resolves the alias to the lead's real seat before sending and waiting, so it reports read when the lead reads it; `memev bus hello all` is refused, because a hello is to one seat.
- memev mcp detects the parent app and refuses or relabels a mismatched client id.
- Codex config.toml: when you already have a [mcp_servers.memev] table, Memev leaves it as-is instead of appending a second one, and says so when it skips it.
- A redirect followed through a proxy now drops what fetch drops: Authorization, cookies and Proxy-Authorization on a hop to another origin, and the body headers when a POST becomes a GET. Before, they went on to the next server unchanged.
- Behind a company proxy, Memev now uses it: every outbound request honours HTTPS_PROXY, HTTP_PROXY and NO_PROXY (either case), with credentials in the proxy URL. The cloudflared download, joining another computer, licence activation and the milestone report all go through it. The daemon on this computer is always reached directly.
- A seat is only ever one computer's. When a second computer has the same short name as the vault's own, its apps get `<app>@<machine>-2` (then -3 and so on) instead of sharing, and posting as, the first computer's seat.
- After `memev bus rename`, messages sent to the old name still reach the seat, holds and comms checks addressed to it still apply, the roster counts its earlier claims and status as its own, and the lead moves to the new name.
- Still to do: the examples in docs/BUS.md and in the bus tool descriptions still show `claude-code@host`.
- On a computer whose short name is not "host", `memev init` ended "Not ready" and exited 1, and `memev doctor` failed "every connected app has a bus seat", because the check still looked for the old `<app>@host` name. It now finds each connected app's seat on this computer by the app, whatever the seat is called. A test runs init and doctor under a real machine name, so the suite's fixed name for its own runs can no longer hide this.
- With MEMEV_NO_SERVICE set, as every test sandbox sets it, Memev never calls launchctl, systemctl or schtasks: `memev service install`, `memev service remove`, `memev uninstall` and `memev doctor --fix` leave the login service alone, and doctor reports it as off. Before, running the tests on a Mac replaced the person's own login service with one pointing at a temporary folder.
- The test cleanup no longer fails the Windows run when Windows still holds a temporary folder for a moment after its daemon stopped.
- The Windows test job on main now passes: tests that check the posix launcher form say so, the temporary folder cleanup retries when Windows still holds a folder, and the vendored parser keeps its bytes on checkout so its checksum test holds.
- The test helper that locates the package root now converts its file URL to a path properly, so the Windows test job on main finds bin/memev.mjs instead of a doubled drive letter.

- The npm package ships only bin, src, templates, vendor and the published docs: a .npmignore guards the development paths and docs/RELEASING.md is the release checklist. Installing the packed tarball and running `memev init` on a clean machine works.
- The tier pages follow the final tiers, sold by person and enforced by computer count: Personal is one person on up to 3 computers at an early-supporter price; a new Team page (2 to 20 people, 3 computers and 10 cloud connectors per person, pooled; contact us until member keys ship); Business is from 10 people per seat; Enterprise is chosen for compliance needs, not size. The status table lists the hosted backup, the hosted relay and member keys as planned.
- Windows is stated as a preview in the README and the quickstart, with what differs there: where Memev keeps its files, the user PATH, the access-list privacy check and no start at login yet. The lab plan has a Windows 11 section (T-WIN-01 to T-WIN-09).
- `memev bus roster --card` prints a short, shareable summary of your AI team: the apps and the seat count, with no paths, tokens, names or machine names.

- The rules every session follows are now a lean text of under 200 tokens (from 562), sent once per session: by the session-start hook in apps that have one, otherwise in the MCP instructions. The CLAUDE.md, AGENTS.md and GEMINI.md block points at them instead of repeating them, and the no-lead notice stops once the setup session has asked. The fixed cost of a session in an app with hooks falls from about 1,800 to about 820 tokens.
- When GitHub is signed in, `memev init` looks for a private backup whose README is a Memev vault and offers to join that vault before it creates a new one. With no GitHub CLI, or signed out, init makes no GitHub call.
- `memev init` ends with "Finish: restart these apps" and one line for each app it connected, saying how to make that app load Memev (a new session or chat, a restart, or a window reload). Apps load MCP servers and hooks when a session starts, so the session that ran init does not have Memev yet.
- A relay gives a vault one address that stays the same after restarts: the protocol (docs/RELAY.md), a client (`memev cloud relay on|off|status|address`, off by default) and a relay for development and tests. The relay only forwards, so it cannot read tokens.
- When the tunnel address changes, the vault writes a signed address record into its git backup. A joined computer that cannot reach the old address reads that record, checks the host's signature, and switches. A bad signature is ignored.
- `memev report on|off|show|send`: an anonymous milestone report that is off by default, asked once at init, and sends only milestone names, days and a random id to an address you set.
- Activation milestones are worked out on your computer from the vault's own files and kept in onboarding.json; `memev onboarding --milestones` lists them. Nothing is sent.
- docs/METRICS.md says how licence activations and package downloads are counted, with the queries.
- `memev license activate <key>` fetches the signed licence once from a configurable endpoint and verifies it on this computer from then on.
- `memev devices` shows a seats line, "N of M computers", and the doctor and `memev license status` say once that the licence expires within 14 days. The reminder is human output only; it never goes into the AI context.
